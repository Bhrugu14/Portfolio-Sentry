# Portfolio: Next.js + Sanity + GA4 — Design

Date: 2026-08-10
Status: Approved

## Overview

A personal portfolio site with all content (profile, skills, projects,
experience, resume, contact info) managed dynamically in Sanity, rendered by
a Next.js App Router frontend, styled as a modern-minimal light/dark site
with a single indigo accent. Google Analytics 4 tracks visits and resume
downloads as a distinct event.

## Content model (Sanity schemas)

- **`siteSettings`** (singleton document, fixed `_id`) — `name`, `title`
  (tagline), `about` (Portable Text), `profileImage`, `resumeFile` (file,
  PDF), `socialLinks` (array of `socialLink` objects: platform, url),
  `skillCategories` (array of `skillCategory` objects), SEO defaults
  (title, description, ogImage).
- **`skillCategory`** (object) — `name` (e.g. "Frontend"), `skills` (array of
  `skill` objects: `name`, `icon` — either an uploaded image or a string key
  into a bundled icon set).
- **`project`** (document) — `title`, `slug`, `coverImage`, `gallery`
  (image array), `summary` (short text, shown on card), `body` (Portable
  Text, optional — presence of body drives whether a detail page is
  generated), `techStack` (string array/tags), `repoUrl`, `liveUrl`,
  `featured` (bool), `order` (number).
- **`experience`** (document) — `role`, `organization`, `logo`,
  `type` (select: `work` | `education`), `startDate`, `endDate` (nullable =
  present), `description` (Portable Text), `order`.
- **`contactSubmission`** (document) — `name`, `email`, `message`,
  `submittedAt`. Created server-side only (API route, write token); never
  queried by the public frontend. Gives a Studio-visible backup of every
  submission alongside the email notification.

Relationships: none need `reference` fields — projects/experience are
independent lists, `siteSettings` embeds skills/social links directly as
objects since they have no independent lifecycle.

Let Sanity generate `_id` for ordinary documents (`project`, `experience`,
`contactSubmission`). `siteSettings` uses a fixed, explicit `_id`
(`siteSettings`) as a controlled singleton.

## Frontend pages

- `/` — single scrolling page: Hero, About, Skills, Projects (grid of
  cards, "featured" first), Experience (unified work+education timeline
  sorted by date), Contact (form + social links), Footer.
- `/projects/[slug]` — optional case-study page, only linked from a
  project card when that project's `body` is non-empty; otherwise the card
  links straight to `repoUrl`/`liveUrl`.
- Single aggregated GROQ query for the home page (one round trip) using
  `defineLive` for fresh, cache-integrated data and draft-mode preview
  support.

## Visual design

- Modern minimal. Neutral black/white/gray base, light + dark mode via
  `next-themes` (respects system preference, manual toggle in header).
  Single accent: electric indigo/violet (`#6366f1` family) for links,
  buttons, highlights, focus rings.
  - Light mode: background `#ffffff`/`#fafafa`, text `#18181b`, accent
    `#6366f1`, borders `#e4e4e7`.
  - Dark mode: background `#0a0a0b`/`#111113`, text `#f4f4f5`, accent
    `#818cf8` (lighter indigo for contrast), borders `#27272a`.
- Sans-serif via `next/font` (Geist or Inter).
- Subtle scroll-reveal animations (Framer Motion) on section entry only —
  fade + slight upward slide, respecting `prefers-reduced-motion`.
- Fully responsive (mobile-first), semantic HTML, visible focus states.

## Analytics & resume tracking

- GA4 via `@next/third-parties/google`'s `<GoogleAnalytics gaId="G-XXXXXXX" />`
  in the root layout — standard pageview/visitor/device/geo tracking, no
  extra code needed for that part.
- User will create the GA4 property (walkthrough provided separately) to
  obtain the Measurement ID before this is wired in; ID stored as
  `NEXT_PUBLIC_GA_MEASUREMENT_ID`.
- Resume download link is a small client component that fires
  `gtag('event', 'resume_download', { file_name, link_url })` on click
  before navigating, so downloads show as a distinct event in GA4
  (Reports → Engagement → Events), separate from generic pageviews.

## Contact form

- `web/src/app/api/contact/route.ts`: validates payload (name, email,
  message; honeypot field for spam), writes a `contactSubmission` document
  to Sanity using a server-only write token (`SANITY_API_WRITE_TOKEN`,
  never imported by client code), and sends a notification email via
  Resend (`RESEND_API_KEY`).
- Client form component shows pending/success/error states inline, no
  page reload.
- Both secrets are server-only env vars, read only inside the route
  handler — never re-exported from a shared module a client component
  could import.

## Environment variables

`web/.env.local`:
```
NEXT_PUBLIC_SANITY_PROJECT_ID=m678av4z
NEXT_PUBLIC_SANITY_DATASET=production
NEXT_PUBLIC_GA_MEASUREMENT_ID=G-XXXXXXX
SANITY_API_WRITE_TOKEN=...        # server-only
RESEND_API_KEY=...                # server-only
CONTACT_EMAIL_TO=<user's email>   # server-only
```

## Deployment

`web/` deploys to Vercel (no custom domain yet — `vercel.app` URL).
`studio/` deploys standalone to `*.sanity.studio` via `npx sanity deploy`.
CORS origins updated to include the Vercel URL (and `localhost:3000` for
dev) via `npx sanity cors add`.

## Testing / smoke test plan

Before calling setup complete:
1. `npm run dev` runs both Studio and web concurrently.
2. Home page renders all sections from real Studio content (not
   placeholders).
3. Click a project card into `/projects/[slug]` via in-app `<Link>`, then
   reload that page directly (SSR check).
4. Submit the contact form — confirm the email arrives via Resend and the
   `contactSubmission` document appears in Studio.
5. Click the resume download link — confirm GA4 Realtime shows the
   `resume_download` event and the correct PDF downloads.
6. Toggle light/dark mode, check responsiveness at mobile width.
7. Browser console clean — no `ReferenceError: process is not defined`,
   no hard reloads.
